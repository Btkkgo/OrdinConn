# Security Policy

## Reporting a vulnerability

Do not disclose exploitable details, credentials, customer data, private account information, or reproduction secrets in a public GitHub Issue.

Use GitHub's private vulnerability reporting feature for this repository when available. If it is unavailable, open a public Issue containing only a request for a private reporting channel; do not include the vulnerability details.

## Sensitive material

Never submit API keys, access or refresh tokens, passwords, cookies, sessions, private keys, SSH keys, wallet recovery phrases, verification codes, personal identity records, banking information, or private application captures.

## Scope

Security reports may cover permission bypasses, secret exposure, Evidence provenance violations, approval-capability failures, unsafe tool execution, mobile redaction failures, or public-sync gate bypasses.

The project will record a sanitized fix and verification result after remediation. A public deletion commit is not considered sufficient remediation for an exposed secret; rotate or revoke it first.
