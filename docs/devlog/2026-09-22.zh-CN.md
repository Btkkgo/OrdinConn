## 公开交互摘要 — Issue #4 并行 Runtime 夹具

- **时间：** 2026-09-22（Asia/Shanghai）
- **阶段：** Runtime Reliability 与 Test Infrastructure；Mobile M2 尚未开始。
- **GitHub Issue：** [#4 — Rust AVD lifecycle and subprocess tests fail under parallel execution](https://github.com/Btkkgo/OrdinConn/issues/4)
- **用户目标：** 找到并消除默认并行测试的间歇性失败，不削弱生产 Deadline，也不重写 M1.5 既有验收。
- **Codex 检查内容：** 当前 `main`、Issue #4 与历史失败、Product Baseline、Process/AVD Helper、Pipe 和 Process-group 生命周期、夹具临时路径、环境/全局状态、Timeout 行为、相关测试、真实 Android 设备状态与公开文档规则。
- **Codex 变更内容：** 增加四工作线程并发 AVD 回归测试，各自拥有独立的 SDK/ADB/Emulator/AVD 夹具，并使用受控冷启动延迟；把有界的成功路径夹具预算与刻意验证短超时的测试分开；更新长期 GitHub/X 发布规则并同步双语公开记录。生产 Runtime Code 与 Deadline 未改动。
- **变更文件：** `AGENTS.md`、Desktop Mobile Tests、英中双语 Build in Public 与 X 规则页面、Current Status、Issue #4 记录、Problems and Solutions、Codex Field Notes 及本成对 DevLog。没有新增 X Draft。
- **发现的问题：** 改动前十次 Default-parallel Desktop 的第一次由同样四个用例形成 24/28，随后九次热态运行通过；四个用例各自单独运行 20 次通过。成功路径的一秒夹具预算把冷态外部进程启动耗时误当成功能行为。真实 Android Smoke 首次在冷启动后正确拒绝白名单外的 Launcher。本地全引用安全门还会扫描本分支以外有意保留、仅存本地的隐私修复备份。
- **解决方案：** 成功的 Large-output/Inherited-pipe 用例使用两秒测试专用预算，成功的 AVD Lifecycle 用例使用三秒；30ms Command-timeout、50ms No-boot 测试、生产 Timeout、Process-group Cleanup 与默认并行执行保持不变。在专用 AVD 上打开 Settings，然后不扩大白名单地重跑同一 Smoke。
- **执行的命令与测试：** 改动前十次默认并行 Desktop；四个具名用例各单独运行 20 次；相关热态测试在八线程和 32 线程下各运行 20 次；并发冷启动回归 RED→GREEN；改动后二十次默认并行 Desktop；十次完整默认并行 Workspace；一次八线程 Desktop；切换前台前后的真实 Android Smoke；`cargo fmt --all -- --check`；禁止 Warning 的 Clippy；Rust Workspace Build；31 个 TypeScript 测试；TypeScript Typecheck；Vite Build；Tauri macOS Bundle；公开文档校验；Working-tree Sanitizer 与当前分支 Identity Scan；隔离公开分支安全门；`git diff --check`。
- **结果：** 新回归在原一秒预算下失败，仅调整测试专用预算后通过。改动后 Desktop 20/20 次通过，每次 29/29；Workspace 10/10 次通过，每次 136 项；八线程 Desktop 29/29。首次 Android Smoke 因前台 Launcher 不在白名单内而报告 `FRAME_CAPTURE=FAIL` 与后续 `BLOCKED`；随后在 Settings 前台原样运行的 Smoke 十项全部通过，包括 Frame、UI Tree、`MobileObservation`、Workspace Projection 与逻辑关闭。Rust/TypeScript 静态检查与 Build 通过。本地全引用安全门报告保留备份；当前分支和 Working Tree 通过定向检查，完整安全门在 Issue 分支及已合并 `main` 的隔离检出中均通过。PR #6 以 `52e73ca` 合并，Issue #4 已关闭。M1.5 继续保持 15 PASS / 0 FAIL / 0 BLOCKED / 0 NOT RUN；M2 仍为 NOT STARTED。
- **剩余风险：** 新受控冷启动回归让 Desktop 套件比原先约 0.5 秒的热态运行慢约两秒。现实调度波动可能超过任何有限测试预算；Issue 继续保留精确的历史失败。逻辑 Session Shutdown 没有终止用户拥有的 AVD。
- **建议下一步：** 只有新任务明确授权后，才考虑 Mobile Intelligence M2 — Verified Navigation。
- **Codex 工程笔记：** 绿色重跑不等于确定性测试。受控延迟与重复默认并行测试揭示了测试中的意外性能断言，同时没有改变生产安全边界。
