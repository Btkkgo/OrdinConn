## Public Interaction Summary — Persistent macOS GitHub sync

- **Timestamp:** 2026-09-20 (Asia/Shanghai)
- **Stage:** GitHub Public Sync system-level scheduling repair
- **GitHub Issue:** [#2 — Establish Public Development Logging and GitHub Source of Truth](https://github.com/Btkkgo/OrdinConn/issues/2)
- **User Goal:** Make the two-hour public GitHub sync run independently of Codex and ChatGPT while preserving the documentation-only security boundary.
- **What Codex inspected:** The previous plist, installer, sync allowlist, credential helper, launchd state, structured logs, macOS TCC events, and the exact background process attribution.
- **What Codex changed:** Moved the runner and working directory into Application Support; added a dedicated, ad-hoc-signed `OrdinConn GitHub Sync` launcher; retained the repository-owned fail-closed sync logic; added explicit tool paths, structured status fields, 5 MiB log rotation, and installer tests; and kept X publishing outside automation.
- **Files changed:** macOS GitHub sync installer, uninstaller, runner/plist templates, dedicated launcher source and metadata, tests, Current Status, Build in Public documentation, Issue record, and this DevLog.
- **Problems discovered:** Moving only the shell script was insufficient. TCC logs proved that `/bin/bash` remained the responsible process and was denied `Documents` access. The installed Command Line Tools SDK also failed to link on macOS 27, so the installer had to select the active full-Xcode compiler and SDK explicitly.
- **Solution:** Give the narrow OrdinConn launcher its own macOS privacy identity, keep the shell runner outside `Documents`, and let the launcher spawn the runner. Do not grant broad access to Terminal or `/bin/bash`. Use Git's `osxkeychain` credential helper rather than placing a token in the plist, runner, or repository.
- **Commands and tests executed:** Shell syntax checks; installer rendering/compile/uninstall test; allowlisted sync integration test; sanitizer and public-repository security tests; public document validation; `plutil`; `codesign`; `launchctl bootstrap`, `print`, and `kickstart`; TCC log inspection; remote commit verification; and a second no-change run.
- **Result:** The primary scheduler is `com.ordinconn.github-sync`, runs at load and every 7,200 seconds, and has no Codex dependency. Its structured log records repository, branch, scan, changes, commit, push, error, and status without credentials. The final real change/push and no-change evidence are posted to Issue #2.
- **Remaining risks:** The launcher has an ad-hoc local signature, so reinstalling or replacing its binary may require macOS Documents permission to be granted again. Product runtime and Mobile M1.5 were not changed.
- **Next recommended step:** Leave the LaunchAgent as primary and keep the Codex heartbeat paused unless it is intentionally used as a recovery fallback.
- **Codex engineering note:** macOS privacy attribution follows the responsible executable, not merely the location of the shell script; a narrow identity is safer and more reliable than granting a general-purpose interpreter broad access.
